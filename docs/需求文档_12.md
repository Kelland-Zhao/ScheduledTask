# 需求文档 12 — Workcenter 机台主数据维护提醒

> **模块**：`12 - Workcenter数据同步.js`（定时 08:20 + 菜单「Workcenter数据同步」）
> **版本**：V20261001.31
> **背景**：模块 12 每天把 Line Database 的新机台追加进 Workcenter 表，只填程序列（A–L、S），人工列（M–R、T）留空。此前**没有任何机制通知人工去维护**——新机台会一直以"责任人空白、机型空白"的状态存在；EDS「注塑机台主数据」维护页（2026-10-01 上线）是维护这些列的唯一入口，但页面本身不做通知（其设计文档明确"邮件通知、定时触发器"不在范围）。
> **目标**：M–R 人工列未补齐的机台（非报废/闲置）每天提醒一次，直到补齐；提醒只从模块 12 发出。

---

## 1. 判据（哪些机台进提醒名单）

**公式**：`Final Machine Type ≠ NA` **且** 六个人工列 `机型 / 设备类型1 / 设备类型2 / 自动化类型 / 责任人 / 备份责任人` 中**任一为空**（trim 后）→ 进名单。

| 规则 | 说明 |
|---|---|
| `J = NA` 排除 | 报废/闲置机台不要求维护（45 台） |
| **S（工艺无需检查Y/N）不参与** | 它是模块 12 每日派生的程序列，不是人工列 |
| **T（点检无需检查Y/N）不参与** | 空 = "需要点检"，是合法默认值；只有"排除点检"时才人工标 Y |
| 值 `NA` 是"已维护" | 各列约定：不适用时显式填 `NA`，留空即未维护 |
| 重复机台号 | 取第一条（沿用模块 12 同步的取首行规则） |
| 名单顺序 | 表内行序；`本次新增` 标记来自本次同步的追加集合 |

## 3. 发送时机

- **只在同步成功写入后**判断与发送；名单为空不发信（不产生空邮件）
- 同步被安全阀/表头校验中止 → 不发信
- 定时运行发真实收件人；手动运行只发操作者
- **邮件失败绝不影响同步结果**：自捕获，Log 摘要里注明（主状态仍是"成功"）
- 表头缺 M–R 任一人工列 → 跳过提醒（记 console 警告），同步照常

## 4. 邮件形态（遵循 `docs/邮件UI规范.md` 模式 A，900px 提醒类）

- 主题：`【机台主数据维护】 N 台机台属性未补齐 - {yyyy-MM-dd}`
- 发件人名：`机台主数据维护提醒`
- 正文：红底头部 → 橙色提示句（请在 EDS 维护页补齐）→ 表格（机台号｜车间｜缺失字段｜类型）+ 两个链接（EDS 维护页、Workcenter 表）→ 标准尾部
- 维护页链接**不直达内页**：指向 `?v=home_new_1.0&next=INJ_MachineMaster`——未登录的人点进去先落 EDS 登录页，登录成功后自动回到维护页；直接把 `?v=INJ_MachineMaster` 贴进浏览器也会被维护页兜底弹回登录页
- 类型列：`本次新增`（本次同步追加）/ `待补齐`（存量未补齐）
- 车间按机台号第 2 位推：0/1→TB1、2→TB2（与模块 13 同规则）

## 5. 测试入口

`testWorkcenterMaintenanceReminder()`：只读生产表、只发操作者，可安全随时运行；不注册菜单项。

## 6. 明确不做（YAGNI）

- 不改 EDS 侧的机台属性数据、判据、收件人；不标黄/不动背景色（为"入口必须先登录"在 EDS 侧加的登录跳转见 §4，只动跳转链路、不碰数据）
- 不逐人分派（新机台责任人为空，无人可派）
- 不新增定时/菜单配置（08:20 定时与手动入口已存在）
- 不设宽限名单（不做历史豁免状态）

## 7. 风险与已知边界

| 项 | 说明 |
|---|---|
| **首日历史遗留上榜** | 上线时 5 台缺机型组 + 8 台缺责任人（共 13 台活跃机台）立即入列，每天提醒直到补齐 |
| **空白宽严度** | 手册（EDS 维护页）说"设备类型/自动化类型找不到选项可先留空"；本判据仍视空白为未维护。若出现长期合法空白的噪音，可将这两列移出判据 |
| **S 列归属冲突（本次不处理）** | EDS 维护页把「工艺免检」做成可勾选并会写入 S；模块 12 每天 08:20 无条件重算覆盖 S —— **人工勾选会被次日静默擦除**。应另行决定：模块 12 保留人工值，或 EDS 将该列锁为只读 |
| **依赖 userID 表列位** | 读 J/O/P 列（0-based 9/14/15），与模块 13/33 相同；表结构变化需同步调整 |
| **维护入口登录门槛只在界面层** | 部署访问级别本就是 DOMAIN（仅 colpal.com 账号，匿名访问被 Google 挡在登录页）；本次补的是 EDS 自身登录门槛：链接先落登录页 + 维护页未登录兜底。未动 OAuth 授权，拿控制台直接调后端接口仍可读写（前提仍是域内账号）——要彻底堵死需另做服务端身份校验 |
