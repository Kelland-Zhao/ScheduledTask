# 需求文档 — 34 - 备件到货提醒

## 一、项目背景

备件采购到货后存放在备件房，申请人需要及时领用。当前后端表「备件项目采购未领出报告」已按公式计算好各备件的在备件房天数（K列，外部程序每日更新）与超期提醒（L列：紧急采购>3天、项目采购>30天），但**缺少到货通知机制**——申请人往往不知道自己的备件已到货，导致备件长期滞留备件房。

需要新增自动化提醒模块：备件到货第一天即通知申请人领用，此后只要未领出就每天提醒，直至领出（记录从后端表消失）自动停止。

## 二、核心功能

每天 08:30 扫描后端报告 tab，对每一条未领出记录（未领用数量>0）提醒对应申请人：

- **第一天到货**（K列在备件房天数 = 0）：告知"您申请的备件已到货，请到备件房领用"
- **持续提醒**：只要记录仍在报告中，每天继续提醒，邮件中展示在备件房天数与超期标记（L列超期提醒原文展示）
- **自动停止**：领出后记录从报告 tab 消失（FILTER 公式过滤掉 未领用数量<=0 的行），提醒自动停止

**无需去重状态表**：报告 tab 的存在性即状态。每天 08:30 定时跑一次，重复执行无害（同一天多跑只会重发当天的提醒邮件，符合"每天提醒"语义）。

## 四、业务规则

### 4.1 扫描范围
- 读取 `未领出备件报告` A1:O 数据区（该 tab 的 FILTER 公式已保证只含 未领用数量>0 的记录）
- 跳过 A列（备件#）为空的行
- 不做日期窗口过滤、不做天数阈值过滤——报告里的每条记录都提醒

### 4.2 收件人解析
- 按 D列申请人姓名，经姓名预处理（去掉 `-Z` / `_QC` 类后缀，复用 08 号模块 `_cf_normalizeName` 模式）匹配 userID 表
- TO = 申请人邮箱（J列 GMail）
- CC = 申请人直线上级（BI列）+ `kelland_zhao@colpal.com`
- 姓名匹配不到 → 该条记录不发给任何人，改为汇总进一封「未匹配人员提醒」邮件单独发给 `kelland_zhao@colpal.com`（列出 备件#/备件名称/PO/申请人姓名），Log 写警告；不影响其他正常发送

### 4.3 聚合发送
- 按申请人聚合：每人每天一封邮件，列出其名下全部未领出备件
- 同一申请人多条记录合并到一封邮件

### 4.4 采购原因展示
- `紧急采购` → 橙色 badge 标记
- `项目采购` → 默认展示
- L列超期提醒非空 → 红色 badge 原文展示

遵循 `docs/邮件UI规范.md`：

| 项目 | 规格 |
|------|------|
| 头部模式 | 模式 C（白色卡片+左侧红色色条，提醒类） |
| 发件人名称 | `备件到货提醒系统`（新模块统一中文命名） |
| 主题 | `【备件到货提醒】{申请人姓名}，您申请的 N 件备件待领用` |
| 内容列 | 备件编码、备件名称、PO、采购原因（badge）、到货日期、在备件房天数（K列，0=今日到货 高亮）、超期提醒（L列红色 badge）、未领用数量、单价/合价（有值才显示） |
| 语言 | 中英双语（中文为主，英文加注） |
| 尾部 | 模式 B（双语，含"自动发送，请勿回复"） |
| 转义 | 所有动态内容经 `escapeHtml()` |
| 最大宽度 | 900px（提醒类） |

**今日到货行**（K=0）：该行天数单元格高亮（如绿色"今日到货"badge），正文开头提示"您申请的备件已到货，请到备件房领用"。

## 七、范围边界

- 仅做"到货提醒 + 每天催领"，不修改后端表任何数据
- 3 天/30 天超期逻辑沿用后端表 L列既有计算，本模块仅展示，不重复实现
- 不涉及企微推送、不做领出闭环回写
