# 需求文档 — 13 号项目：注塑点检机台核对与主数据同步

> 版本：V20260930.1 ｜ 状态：已确认，待实施
>
> 本模块原编号 15，`需求文档_15.md` 为其 v1（仅核对报警）。本文档描述 v2 变更：**新增主数据双向同步**。

## 1. 项目背景

注塑车间有两套机台数据：

- **点检侧**：`Database_PointCheck-点检后台数据` → `MachineList`，实际执行点检的机台清单
- **计划账侧**：`11 - 注塑计划机台`（IM Workcenter in Planning）→ `Workcenter`，注塑计划全量机台台账

v1（现状）每天比对两侧差异、发邮件、把差异类型1 在 MachineList 中标黄，把「更新点检机台主数据」这一步留给人做。

**v2 要解决的**：这一步一直是人工的，邮件里那句「需要更新点检机台主数据」没有任何机制保证被跟进。v2 把它自动化——**比对之后直接同步主数据**。

## 2. 判定依据（本次变更的核心）

### 2.1 纳入集

```
纳入集 = Workcenter 全部行 − （「无需检查Y/N」列 = Y 的行）
```

### 2.2 「无需检查Y/N」列的性质（重要）

该列**不是人工维护列**，是模块 12（`12 - Workcenter数据同步.js`，每日 08:20 运行）的派生输出：

```javascript
// 12 - Workcenter数据同步.js:320-324
out[cols["无需检查Y/N"]] = ((finalType === "6AX" && isMain === "N") || finalType === "NA") ? "Y" : "";
```

- `Final Machine Type = 6AX` 且 `是否主设备 = N` → `Y`
- `Final Machine Type = NA`（已退役）→ `Y`
- 其余 → **写空字符串**（无条件赋值，会覆盖人工填写的内容）

因此：

- **人工标 Y 无法表达意图**——次日 08:20 被擦回空
- 该列虽落在 M–S 区间内，但被模块 12 纳入 `_WS_MANAGED_HEADERS` 主动计算，**不属于受保护的人工列**（M–R 才是：模块 12 的基础行整行复制、不覆写）

### 2.3 数据范围说明

表 11（`IM Workcenter in Planning`）**全部为注塑机台**（实测 326 台），不存在其他工序。`Final Machine Type` 的取值（`HS`/`DP`/`ENG`/`FCS`/`3AX`/`6AX`/`H Auto`/`H Auto S`/`HT160`/`HT250`/`FT400`/`DB`/`NA`）是机型/类型分类，**不是工序**。

### 2.4 废弃的旧规则

v1 的以下规则全部作废：

| 废弃项 | 原用途 |
|---|---|
| `机器性能` 列精确匹配 `闲置`（现有代码第 49 行） | 排除闲置机台 |
| `Final Machine Type ∈ {6AX, DP, HS}` 豁免 | 抑制差异类型2 误报 |
| 指定机台 `V2FTA164/264/364` 豁免 | 同上 |
| 机型 `Plasma` 豁免（差异类型1） | **保留**，见 3.4 |

`机器性能` 的关键字匹配覆盖不全——`报废` 15 台、`机台号报废,原XXX机器闲置` 6 台、`机器闲置，机台号报废` 1 台、`新品设备改造,暂时闲置` 1 台，共 23 台未被排除。且它与「无需检查Y/N」构成两套并行判据。本次收敛为单一判据。

## 3. 核心功能

### 3.1 数据读取

| 侧 | 表 | Sheet | 读取范围 | 过滤 |
|---|---|---|---|---|
| 点检 | `Database_PointCheck` | `MachineList` | `A:E` 全量 | `工序(A列) = INJ` |
| 计划账 | `11 - 注塑计划机台` | `Workcenter` | 按表头名定位所需列 | `无需检查Y/N ≠ Y` |
| 收件人 | 权限表 | `userID` | — | `O列 = INJ` 且 `P列 = S&C`，取 `J列` |

### 3.2 比对与动作

**比对键 = 机台号**（MachineList `D列 机台号` ↔ Workcenter `Workcenter` 列）。

| 情形 | 动作 |
|---|---|
| 纳入集有 / MachineList 的 INJ 行中无此机台号 | **追加**一行到表尾 |
| MachineList 的 INJ 行中有 / 纳入集无此机台号 | **删除**该机台号的全部 INJ 行（Plasma 豁免除外） |

一台机在 MachineList 中可能有多行（因机型/点检人不同，实测 `H2FCS506` 有 `6AX(自动化部分 for FCS)/技术员` 与 `FCS/OPC` 两行），**整组一起进、一起出**。

### 3.3 追加行字段

| 列 | 值 | 来源 |
|---|---|---|
| A 工序 | `INJ` | 常量 |
| B 车间 | 机台号**从左数第 2 个字符**：`0` / `1` → `TB1`；`2` → `TB2`；**其他值 → 留空并计入待补全**<br>例：`H2FCS506` 第 2 位 = `2` → `TB2`；`V1FTA958` 第 2 位 = `1` → `TB1` | 机台号 |
| C 机型 | 空 | — |
| D 机台号 | Workcenter `Workcenter` 列原值（仅 `trim()` 去首尾空白，**保留大小写**，不做大小写转换） | 表11 |
| E 点检人 | 空 | — |

### 3.4 删除范围与豁免

删除仅作用于 `工序 = INJ` 的行。保留一条豁免：

> **`机型(C列) = Plasma` 的 INJ 行不删除**（沿用 v1 的 `exemptType1Process = ["Plasma"]`）

原因：这类机台只存在于点检侧、表11 完全没有，无法用「无需检查Y/N」表达意图。误删会导致**静默失去点检覆盖**。

## 4. 安全不变量

> **工序 ≠ INJ 的行，值和背景色一律不写入。**

MachineList 中含 PK / TF 等其他工序的行（实测 INJ 行分散在至少 3 处：39–72、214–约 460、1051–1058）。三处必须守住：

| 动作 | 边界 |
|---|---|
| 删除 | 只删 `工序 = INJ` 的行；按 **(工序=INJ, 机台号)** 匹配，不可只按机台号 |
| 追加 | 一律 `insertRowsAfter(最后一行, n)` 追加到表尾 |
| 标黄 | 只对 `工序 = INJ` 的行改色；且**只写「目标色 ≠ 当前色」的连续区间**，颜色没变的行一概不写 |

**为何必须带工序条件**：表内 `T1GR0301` 在 TF 工序下有两行（`Zar`/OPC + `Zar-TECH`/技术员）。只按机台号匹配会跨工序误删。

**为何追加到表尾**：INJ 段无唯一边界，插行必然动到其他行。表尾 1051–1056 的 8 行 INJ（`H2FCS506` / `H2HTA520` / `H2FCS301` / `H2FCS302` / `V1FTA958`）是历史追加累积的结果，说明追加到表尾是本表既有做法。

---

## 5. 安全阀

| 动作 | 是否设阀 | 理由 |
|---|---|---|
| 追加 | **不设** | 可逆（删掉该行即可），且属日常动作；设阀会挡住正常业务 |
| 删除 | **设阀** | 不可逆；删除依据是模块 12 算出的标志，若上游异常会批量抹掉点检覆盖且当下无人察觉 |

**规则**：单次运行中删除 **> 10 台机台** → **本次不执行删除**（追加照常执行）。邮件「删除」区块标注状态【未执行·超阈值】。

**Log 记录方式**：状态列记 `成功`（本轮确实部分执行、且发出了邮件 —— 「跳过」会同样失真），被拦的台数与原因写进**摘要列**，形如 `删除=0台(计划N台被安全阀拦下)`。

**计数单位是「机台」不是「行」**——一台机在 MachineList 中可能有多行（如 `H2FCS506` 占 2 行），无论占几行都只计 1 台。判定阈值用「拟删除的机台号个数」，不用「拟删除的行数」。

**人工放行**：手动运行（`e === undefined`）时**绕过安全阀**；定时运行（`e` 存在）时启用。复用现有代码的 `e ? "定时" : "手动"` 判断。

因此**不会死锁**：追加照常推进；删除的积压由人工核对后手动触发一次即可清掉。

## 6. 执行顺序

```
1.  读 MachineList A:E 值
2.  读 Workcenter（按表头名定位列；表头缺必需字段 → 写跳过日志并中止）
3.  算三个集合：追加集 / 删除集 / 待补全集
4.  过安全阀（仅作用于删除集）
5.  按连续区间 deleteRows（仅含 INJ 行）
6.  insertRowsAfter(最后一行, n) + setValues 追加新行
7.  重新读 A:E 背景色（删除会致行上移，不可沿用步骤 1 的矩阵）
8.  按「变色区间」setBackgrounds（仅 INJ 行）
9.  发邮件
10. writeLog
```

任何一步抛异常 → 整轮捕获，Log 记失败，**不发邮件**（避免发出与实际不符的报告）。

## 7. 邮件规范

### 7.1 头部

标题：`【点检同步】 注塑机台差异报告 YYYY-MM-DD`

标题栏下方一行超链接：

- 【点检】`https://docs.google.com/spreadsheets/d/1RQql-PrcBWiAQNeg7hQKcocpllSUMRhT5XPrDTVWoBY/edit#gid=436306312`（MachineList 页签）
- 【表11】`https://docs.google.com/spreadsheets/d/12MXO53wJC8s_J-IE2uGY5jx35rnUE7rxW1xvwVU-FxM/edit#gid=0`（Workcenter 页签）

### 7.2 区块与状态列

| 区块 | 状态取值 |
|---|---|
| 本次追加 | 【已添加·需人工维护】 |
| 本次删除 | 【已删除·因表11标Y】 / 【已删除·表11查不到】 / **【未执行·超阈值】** |
| 待补全 | 【待补全】 |
| 仅报告 | 【仅报告·Plasma豁免】 |

**「已删除」必须拆两种**：因 Y 删的通常正确；因表11 查不到的必须人工复核。

### 7.3 删除快照

被删除的行必须记录 **A~E 全字段整行快照**，写入邮件删除区块和 `writeLog` 的 `remark` 参数。

只记机台号无法恢复——一台机可能有多行。

### 7.4 数据质量告警（可选区块，有才出现）

`无需检查Y/N` 列中**非空且不等于 `Y`** 的值（如小写 `y`、`是`、`不用`）→ 单列一节提示。

否则「标了却没生效」不会被发现。

### 7.5 数据源异常告警

| 异常 | 处置 |
|---|---|
| Workcenter 表头缺必需字段 | 中止，Log 记跳过（绝不用空 map 继续） |
| Workcenter 出现重复机台号 | 取第一条（沿用模块 12 做法），其余在邮件告警 |
| 收件人为空 | 跳过发信，Log 记跳过 |

## 8. 待补全机制

追加行的 `机型` / `点检人` 为空。若不跟进，机台号层面的差异会消失，但机器实际未被安排点检——等于把「看得见的报警」换成「看不见的欠账」。三重暴露：

1. **表内标黄**：`工序 = INJ` 且（`机型` 为空 或 `点检人` 为空）→ A~E 标 `#FFFF00`；非待补全的 INJ 行清除背景。人工补齐后下次运行自动清黄。
2. **邮件「待补全」区块**：每天出现，直到补齐。
3. **状态列**：见 7.2。

该机制同时接替了 v1 中「差异类型1 标黄」的视觉语义（差异类型1 现在直接删除，不再需要标黄）。

## 12. 边界条件

| 场景 | 处理 |
|---|---|
| MachineList 无 INJ 数据 | 跳过，Log 记录 |
| Workcenter 为空 | 跳过，Log 记录 |
| Workcenter 表头缺必需字段 | 中止，Log 记录 |
| 两侧完全一致 | 邮件报告「无差异」，不写入 |
| 机台号大小写/空格不一致 | 比对时 `trim()` + 转大写归一；**写入时保留表11 原值的大小写**（仅 `trim()`，不做大小写转换） |
| 机台号第二位为意外值 | 车间留空并计入待补全（**不猜**） |
| 待补全行已存在（历史遗留） | 计入待补全区块，不重复追加 |
| 手动删除某台待补全行 | 下次运行按机台号缺失重新追加 |
| 收件人为空 | 跳过发信，Log 记录 |
| 单次删除 > 10 台 | 删除不执行，追加照常，邮件标注【未执行·超阈值】 |

## 13. 验收标准

1. 每日 08:25 自动执行；专项菜单可手动触发；预演入口只报告不写入
2. 纳入集正确：`Workcenter` 全部行减去 `无需检查Y/N = Y`
3. 缺失机台被追加到表尾，字段符合 3.3
4. 应删机台的全部 INJ 行被删除，Plasma 行保留
5. **PK / TF 等其他工序的行，值、行序、背景色零变化**
6. 待补全行标黄，补齐后自动清黄
7. 邮件含两个表格超链接、四个区块、状态列、删除整行快照
8. 删除超过 10 台时只报告不执行；手动运行可放行
9. Log 正确记录每次执行状态与删除快照

## 14. 测试要求

### 14.1 必须基于生产表真实数据

测试 fixture **必须取自生产表的真实行值**，不得使用编造的理想化数据。每个 fixture 都要在代码注释里标注取样来源。

已确认的真实数据形态（可直接取用）：

| 跨工序撞号 | `MachineList!A1000:E1060` —— `T1GR0301` 在 TF 下两行 |
| 车间第二位映射 | `H2FCS506`(→TB2)、`V1FTA958`(→TB1) |
| 非 INJ 行保护 | `MachineList!A700:E760`（PK 块）、`A1000:E1050`（TF 块） |
| 表11 标 Y 行 | `Workcenter!A290:S340` —— 40 行 `报废`/`闲置`/`改造` 全部 `S=Y` |
| 同号多行 + S 为空 | `Workcenter` 中 `V2FTA164/264/364`（机器性能 `3AX`，`S` 为空） |

### 14.2 运行方式

沿用现有约定：`tests/pointcheck-sync.test.mjs`，`node --test`，`eval()` 加载源码。

### 14.3 覆盖清单

1. `无需检查Y/N = Y` 的行被排除出纳入集
2. `无需检查Y/N` 非空非 `Y`（如 `y` / `是`）触发数据质量告警，且**不**被当作 Y
3. 表头缺失 → 中止，不写入
4. 车间第二位映射：`0`→TB1、`1`→TB1、`2`→TB2、意外值→留空
5. 同机台号多行：整组一起追加 / 一起删除
6. `机型 = Plasma` 的 INJ 行不被删除
7. **非 INJ 工序行在追加/删除后值、行序、背景色均不变**
8. 删除阈值：11 台 → 删除不执行、追加执行；10 台 → 执行
9. 手动运行绕过安全阀
10. 待补全判定：`机型` 或 `点检人` 为空
11. 标黄只写变色区间
12. Workcenter 重复机台号 → 取第一条 + 告警
13. 机台号 `trim` + 大写归一
14. MachineList 无 INJ 行 / 机台号全空 → 跳过

### 14.4 完成后必须在真实表上验证

单测通过**不等于**在真表上正确。实施完成后必须依次：

1. 在真实表上跑 `dryRunPointCheckSync()`，人工核对「将要追加」「将要删除」清单
2. 确认无误后手动跑一次 `checkPointCheckMachines()`，核对：
   - 追加行的 5 个字段值
   - 删除行确为 INJ 行，且 **PK / TF 行数与内容未变**（跑前跑后各取一次行数与工序分布对比）
   - 邮件四个区块、状态列、两个链接、删除快照
   - Log 记录
3. 待补全行标黄是否正确，非 INJ 行背景色未被改动
4. 把验证结果（含跑前跑后对比数据）回报后，再放开定时执行

## 16. 风险与已知限制

| 项 | 说明 |
|---|---|
| **写入独占性未验证** | 假定 MachineList 由本脚本独占写入。表内存在 `Database for Web`、`Authorization settings`，疑有 Web 端在读。**若点检后台（Web 端）也能增删机台，本模块的删除可能被同步回来或造成两端不一致**——需确认后重新评估 |
| **写入目标未最终确认** | 表内存在 `MachineList（New）`（50500 行）。本模块写入目标为老 `MachineList`，若将来迁移需同步调整 |
| **排除能力受限** | `无需检查Y/N` 由模块 12 派生，**无法手工排除某台特定机台**。若预演发现某台机不该点检、又不属于「6AX非主设备/退役」，需在模块 12 加规则，或新增一列人工开关 |
| 读改写竞态 | 执行时间 08:25，人工编辑概率低但存在；删除窗口内的人工编辑可能被覆盖 |
| 收件人未变更 | 沿用 v1（INJ + S&C）。「删除主数据」影响大于「报告差异」，如需加入计划/主数据负责人，另行变更 |
| 删除无回滚 | 仅靠邮件与 Log 中的整行快照恢复 |
| **删除判定依赖模块 12 的时效性** | 纳入集来自模块 12 每日 08:20 写入的 `无需检查Y/N`。若某日 08:20 那次未执行（触发器异常、上游故障），08:25 会基于**过期的标志**做删除决策，而这一步不会察觉上游没跑。模块 12 自身的同步有安全阀，但那只保护它自己那一步 |
| **上线当日的保护依赖"先预演"** | `isManual` 会绕过安全阀，而首次同步正是手动执行 —— 所以上线当日对异常大批量读数的唯一保护是**先跑预演、人工看过清单**。预演同样绕过阀（它只读），因此它会如实列出"将要追加/删除"的全量，这正是它的作用 |
